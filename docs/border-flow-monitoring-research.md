# پایش مستمر آمار کامیون‌ها و بارهای ورودی/خروجی گذرگاه‌های مرزی ایران
## تحقیق عمیق: منابع، روش‌ها، معماری داده و چارچوب اعتماد

> هدف: داشتن دادهٔ **معتبر، دقیق و کاربردی** از تردد کامیون و جریان بار (با نوع کالا و مقصد) در گذرگاه‌های مرزی ایران، به‌صورت **مستمر** — نه گزارش موردی.
> این سند مکمل `docs/search-and-data-capabilities.md` است و مسیر اجرایی سامانه را مشخص می‌کند.

## بخش ۱ — درس کلیدی تحقیق: «دادهٔ رسمی روزانهٔ همه‌جانبه» وجود ندارد؛ اما ترکیب منابع وجود دارد

یافتهٔ اصلی تحقیق: هیچ منبع واحدی آمار روزانهٔ «تعداد کامیون + نوع کالا + مقصد» برای همهٔ مرزهای ایران منتشر نمی‌کند. اما این داده به‌صورت **پخش‌شده در چند لایهٔ مکمل** وجود دارد:

| لایه | دانه‌بندی زمانی | پوشش کالا/مقصد | اعتبار | دسترسی |
|---|---|---|---|---|
| **۱. اظهارنامه‌های گمرکی (پایهٔ حقیقت)** | روزانه (رویداد ترخیص) | کامل: HS Code، وزن، ارزش، کشور مبدأ/مقصد، گمرک | رسمی/قانونی | سامانه‌های رسمی (نیازمند مجوز یا مشارکت) |
| **۲. آمارهای رسمی منتشرشده** | ماهانه/فصلی/سالانه | کامل در سطح گمرک | رسمی | وب رسمی، اغلب بدون API |
| **۳. سازمان‌های بین‌المللی** | ماهانه/سالانه | جریان تجاری به تفکیک شریک تجاری | رسمی-استاندارد | API رایگان/محدود |
| **۴. مطالعات میدانی کریدوری** | نمونه‌ای/سالانه | زمان/هزینه/رفتار در مرز | روش‌مند (ADB-CPMM) | PDF گزارش‌ها |
| **۵. اخبار و رسانه‌ها** | لحظه‌ای | اعداد موردی صف و تردد | متغیر — نیازمند اعتبارسنجی | جستجوی وب |
| **۶. داده‌های فیزیکی مستقل** | لحظه‌ای تا روزانه | شمارش خودرو، کشتی، واگن | عینی (سنجش مستقیم) | ماهواره/AIS/ردیابی |
| **۷. شبکهٔ مشارکتی میدانی** | لحظه‌ای | صف، وضعیت پذیرش | تجربی — قابل تجمیع | اپ/گزارش راننده |

**نتیجه:** معماری درست، خط لولهٔ چندمنبعی است که لایهٔ ۱ را به‌عنوان «حقیقت زمین»، لایه‌های ۲–۴ را به‌عنوان «کالیبراسیون»، و لایه‌های ۵–۷ را به‌عنوان «سیگنال بلادرنگ» می‌گیرد و همه را با چارچوب اعتماد قابل‌توضیح ادغام می‌کند.

### ۲.۱ منابع رسمی ایران

### ۲.۳ داده‌های فیزیکی مستقل (سنجش عینی)

| منبع | چه می‌دهد | وضعیت فناوری |
|---|---|---|
| **تصاویر ماهواره‌ای + بینایی ماشین** | شمارش کامیون در صف و پارکینگ مرز؛ تخمین AADT از ردپای حرکت (smear) بین فریمها | اثبات‌شده (ESA، TTI، Satellogic، climatechange.ai)؛ تصویر مکرر تجاری: Planet، EOS، Satellogic؛ رایگان: Sentinel-2 (۵ روزه، رزولوشن ۱۰m) |
| **AIS دریایی** | ورود/خروج کشتی به بنادر مقصد نهایی بار | رایگان: AISStream.io؛ نمونهٔ نهادی: IMF PortWatch (سطح UN Global Platform، ۲۰۶۵ بندر) |
| **GPS ناوگان** (با رضایت) | توقف/تردد کامیونهای همکار | نیازمند مشارکت کریری‌ها |
| **کوئری تلفن همراه/پارکینگ** | سیگنال تراکم پارکینگ‌های مرزی | محدود و حساس؛ مکمل |

### ۲.۴ لایهٔ خبری (سیگنال بلادرنگ)

رسانه‌ها روزانه اعداد موردی منتشر می‌کنند (نمونه‌های زندهٔ همین تحقیق): «۱٬۸۶۳ کامیون از پرویزخان در یک روز»، «۲٬۲۴۹ کامیون پشت مرز ریمدان»، «۹۰۳ کامیون از ریمدان در ۲۴ ساعت»، «۲٬۵۰۰ کامیون متوقف در بازرگان». این‌ها **سیگنال** هستند نه دادهٔ قطعی؛ ارزششان در فرکانس بالاست و خطایشان در فرایند اعتبارسنجی کنترل می‌شود (بخش ۵).

## بخش ۳ — معماری پیشنهادی خط لولهٔ داده (۵ مرحله)

```
┌─────────────────────────────────────────────────────────────────────────┐
│  ۱) گردآوری (Collectors)          ۲) نرمال‌سازی (Normalize)             │
│  ├─ اسکرپر اتاق تهران (HS×گمرک×ماه) ├─ استخراج ساختاریافته با مدل زبانی │
│  ├─ اسکرپر IRICA/RMTO/راه‌آهن      ├─ نگاشت نام گمرک به گذرگاه اطلس      │
│  ├─ خوانندهٔ PDF (ADB/UNECE)       ├─ یکسان‌سازی HS (H2/H4/H6)           │
│  ├─ زنجیرهٔ خبر (Exa+RSS)          ├─ نرمال‌سازی فارسی (normalizeFa)     │
│  ├─ Comtrade API                   └─ جفت‌سازی ورودی/خروجی و آینهٔ طرف    │
│  └─ (آینده) ماهواره/AIS/میدانی                                            │
├─────────────────────────────────────────────────────────────────────────┤
│  ۳) اعتبارسنجی (Validate)         ۴) ادغام و رفع تعارض (Fuse)           │
│  ├─ بازه‌های منطقی (وزن/ارزش/تعداد) ├─ انتخاب منبع برتر به تفکیک قلمرو   │
│  ├─ آزمون نوسان غیرممکن (پرش>۵۰٪)  ├─ وزن‌دهی اعتماد (بخش ۵)            │
│  ├─ تطبیق دوگانه با منبع آینه      ├─ تخصیص مقصد واقعی (کشورِ مقصد      │
│  └─ قرنطینهٔ رکورد مشکوک            │   کشور مرزی ≠ مقصد نهایی)          │
│                                     └─ برچسب confidence روی هر رکورد     │
├─────────────────────────────────────────────────────────────────────────┤
│  ۵) انتشار (Serve)                                                      │
│  ├─ API داخلی: /api/border-flow?gate=&from=&to=&hs=                     │
│  ├─ لایهٔ نقشه: عارضهٔ گذرگاه با بار روز/هفته/ماه + روند                  │
│  ├─ خروجی GeoJSON/Excel/CSV برای گزارش                                  │
│  └─ داشبورد روند: کریدور، فصل، نوع کالا (HS2)، مقصد                     │
└─────────────────────────────────────────────────────────────────────────┘
```

### جزئیات فنی مراحل

**۱) Collectors** — هر منبع یک کلاس مستقل با `timeout`، `retry`، هش محتوا و ثبت `lastModified`؛ تغییر صفحهٔ منبع → هشدار شکست اسکرپ.

**۲) Normalize** — مدل زبانی سازمانی موجود سامانه (`gpt-6-luna`) متن فارسی خبر/اطلاعیه را به JSON ساختاریافته تبدیل می‌کند:
```json
{ "gate": "بازرگان", "direction": "export", "trucks": 2500,
  "event": "queue", "date": "1404-07-12", "source": "asriran.com", "quote": "…" }
```
نگاشت نام‌ها به شناسهٔ گذرگاه اطلس با همان گازتیر موجود (`geoTagging.ts` — ۲۰۰+ نام، نرمال‌سازی «ی/ک/اعراب/نیم‌فاصله»).

**۳) Validate** — قواعد سخت: ارزش دلاری/وزنی مثبت، نسبت ارزش به وزن در بازهٔ منطقی HS، هم‌جهت بودن جریان با شریک تجاری آینه (Comtrade)، پرش روزانهٔ >۵۰٪ در مرز معمولی → قرنطینه تا تأیید.

**۴) Fuse** — تقدم منبع به تفکیک قلمرو، نه مطلق:
- **وزن/تعداد کامیون از مرز مشخص:** اسکرپر اتاق تهران (رسمی، دانه‌بندی بالا) > RMTO > CPMM > خبر > ماهواره
- **مقصد نهایی:** Comtrade/آینهٔ طرف مقابل > کشور اعلامی اظهارنامه > حدس خبر
- **زمان واقعی:** خبر/میدانی/ماهواره > آمار رسمی (تأخیر انتشار)

**۵) Serve** — همان الگوی موجود سامانه: هر رکورد با `provenance` (منبع، نشانی، تاریخ اخذ) و `confidence` منتشر میشود؛ خروجی GeoJSON فعلی سامانه (`buildSearchGeoJSON`) عمومیت می‌یابد.

## بخش ۴ — مدل دادهٔ پیشنهادی (حداقلِ کافی و مقیاس‌پذیر)

```ts
interface BorderFlowRecord {
  id: string;                    // hash(gate+date+direction+hs+source)
  gateId: string;                // شناسهٔ گذرگاه در اطلس (DATA.crossings)
  date: string;                  // ISO یا شمسی نرمال‌شده
  direction: 'import' | 'export' | 'transit-in' | 'transit-out';
  trucks?: number;               // تعداد کامیون (در دسترس)
  tonnage?: number;              // تن
  valueUsd?: number;
  hs2?: string; hs6?: string;    // نوع کالا
  partnerCountry?: string;       // کشورِ آن‌سوی مرز
  finalDestination?: string;     // مقصد نهایی (از آینه/اظهارنامه)
  source: 'tccim' | 'irica' | 'rmto' | 'comtrade' | 'cpmm' | 'news' | 'field' | 'satellite' | 'ais';
  sourceUrl?: string;
  confidence: 'high' | 'medium' | 'low';
  collectedAt: string;           // مُهر اخذ (lineage)
}
```
هر پرسش کاربر («ماه گذشته چزابه خروجی چه بود؟») → فیلتر مستقیم روی این جدول + مقایسه با روند تاریخی از لایهٔ رسمی.

## بخش ۵ — چارچوب اعتماد: امتیاز اعتبار چندمنبعی

الگوبرداری از روش‌شناسی ADB-CPMM (سنجش میدانی استاندارد زمان/هزینهٔ مرز) و تجربهٔ نهادی IMF/OECD در استفادهٔ AIS برای برآورد تجارت:

```
confidence = base(منبع) × fresh(تازگی) × agreement(هم‌رأیی)
```
| مؤلفه | قاعده |
|---|---|
| **base** | اظهارنامه/آمار رسمی گمرک = ۱٫۰ · RMTO/راه‌آهن = ۰٫۹ · Comtrade = ۰٫۹ · CPMM = ۰٫۸ · ماهواره = ۰٫۷ · خبر رسانهٔ معتبر = ۰٫۵ · گزارش میدانی تأییدشده = ۰٫۵ · میدانی تک‌منبع = ۰٫۳ |
| **fresh** | کاهش خطی با تازگی: روزانه ۱٫۰ → ماه ۰٫۹ → فصل ۰٫۸ → سال ۰٫۶ |
| **agreement** | دو منبع مستقل هم‌رأی (اختلاف <۲۰٪) = ×۱٫۰ · یک منبع = ×۰٫۸۵ · تعارض = ×۰٫۶ + هشدار |
| انتشار | رکورد <۰٫۵ فقط به‌صورت «نیازمند تأیید» نمایش داده میشود، نه عدد قطعی |

هر عددِ نمایش‌داده‌شده در رابط کاربری: **منبع + تاریخ + دانه‌بندی + امتیاز اعتماد** (الگوی «چرا این عدد؟»).

## بخش ۶ — نقشهٔ راه اجرایی (فازبندی واقع‌بینانه)

**فاز ۰ — هفتهٔ ۱–۲ (شروع فوری با امکانات موجود):**
1. اسکرپر اتاق تهران (`service.tccim.ir/stats`) — منبع آزمایششدهٔ همین تحقیق: گمرک×کشور×HS×ماه×وزن×ارزش با خروجی Excel.
2. تبدیل گازتیر موجود سامانه به جدول نگاشت «نام گمرک رسمی → گذرگاه اطلس».
3. آیندگان خبری روزانه با زنجیرهٔ فعلی (Exa + استخراج ساختاریافتهٔ مدل زبانی) برای ~۱۰ مرز پرترافیک.

**فاز ۱ — ماه ۱–۲:**
4. صفحهٔ «جریان مرزها»: داشبورد ورودی/خروجی به تفکیک گذرگاه/ماه/HS2 با امتیاز اعتماد.
5. ماتریس مقصد: گمرک × کشور (از همان داده) + رفع ابهام «کشور مرزی ≠ مقصد نهایی» با Comtrade.
6. آلارم نوسان: پرش غیرعادی تردد/تناژ در هر مرز → کارت هشدار روی نقشه.

**فاز ۲ — ماه ۲–۴:**
7. خوانندهٔ گزارش‌های PDF (ADB-CPMM، UNECE، ECO) به جدول زمان/هزینهٔ مرز.
8. سامانهٔ گزارش میدانی (فرم + اعتبارسنجی مکانی + وزن گزارش‌دهنده) — الگوی CPMM.
9. یکپارچه‌سازی Comtrade API برای آینهٔ طرف مقابل و مقصد نهایی.

**فاز ۳ — ماه ۴+ (بشتاب‌دهندهٔ اعتبار):**
10. پایش ماهواره‌ای صف ۵ مرز اصلی (Sentinel-2 رایگان برای شروع؛ تجاری برای فرکانس).
11. AIS بنادر مقصد برای مقاصد نهایی بار دریایی.
12. رایزنی نهادی: دسترسی دادهٔ EPL گمرک (سطح مشارکت داده) — جهش کیفی به «حقیقت زمین» روزانه.

## بخش ۷ — ریسک‌ها و پادزهر

| ریسک | پادزهر |

| تغییر ساختار سایت‌های منبع | کانال‌های JSON/Excel محترمانه اول؛ اسکرپ DOM فقط آخر؛ تست رگرسیون هفتگی ساختار |

## جمع‌بندی
مسیر واقع‌بینانهٔ «دادهٔ معتبر و مستمر» نه یک منبع جادویی، بلکه **خط لولهٔ چندمنبعی با حکمرانی اعتماد** است: حقیقت زمین از اظهارنامهٔ گمرکی (از راه اتاق تهران امروز و EPL فردا)، کالیبراسیون از سازمانهای بین‌المللی، سیگنال بلادرنگ از خبر و میدان، و پادزهر سوگیری از سنجش فیزیکی مستقل. سامانه فعلی (گازتیر، استخراج ساختاریافتهٔ مدل زبانی، GeoJSON، امتیاز اعتماد) دقیقاً زیرساخت همین خط لوله است؛ فاز ۰ آن با یک اسکرپر و یک داشبورد همین هفته شروع می‌شود.
